# GloriaSetup rollout

Pushing a tag like `v0.4.0` runs `.github/workflows/release.yml`, which builds the Tauri app, packs it with
`projectGloria/GloriaSetup@v0.1.0` and attaches `CS2Craft_<version>_x64-setup.exe` to the release.

## Please

- Add the repo secrets `WINDOWS_PFX_BASE64` and `WINDOWS_PFX_PASSWORD`. Without them the setup is built unsigned.
- Nothing was built or run locally, so the first tag push is the first real test of the workflow.
- Versions: `package.json`, `Cargo.toml` and `tauri.conf.json` say 0.4.0 (the launcher catalog says 0.3.0). `gloria.toml`
  uses 0.4.0. The tag version overrides it when packing; keep the project files in step with the tag.
- Main exe `cs2-craft.exe` comes from the Cargo package name; confirm it after the first CI run.
- Runtime files copied to `app-dist/` are the exe plus `resources/` (catalog.json, color-corrections.json, licenses/,
  viewer/), matching how the code reads `resource_dir()/resources/...`. `resources/viewer` is generated by
  `npm run build`, which downloads Source2Viewer-CLI 20.0 from GitHub.
- The app is built with `tauri build --no-bundle`, so the old NSIS installer is no longer produced in CI.
- `data_folders` lists only `%LOCALAPPDATA%\com.cs2craft.catalog` (database, cached images/models and prices all
  live under the app local data and cache dirs, which are the same folder for this identifier).
- `legacy_names = ["CS2 Craft"]` is the Tauri `productName`, which the old NSIS installer used as its DisplayName.
- The icon is the existing `src-tauri/icons/icon.ico`; no icon files were created or changed.
- The release is created by the workflow if it does not exist, with generated notes.

## Fix: v0.4.0 release run did not attach the setup

- The failure `accepts at most 1 arg(s), received 3` came from the "Make sure the release exists" step in `.github/workflows/release.yml`: `gh release view $env:TAG 2>$null` let `gh` see the redirection as extra positional arguments, so the step failed before GloriaSetup ran.
- The step now runs `gh release view $env:TAG -R $env:GITHUB_REPOSITORY --json tagName | Out-Null` (no stderr redirection), and `gh release create` also gets `-R`.
- Versions were already 0.4.0 in `package.json`, `package-lock.json`, `tauri.conf.json`, `Cargo.toml`, `Cargo.lock` and `gloria.toml`, so nothing changed there.
- Not run locally; the tag was not pushed or moved. The release needs a re-run after this commit is on the tag's ref.
